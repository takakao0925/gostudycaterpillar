# 循環模式（Cycle Mode）規格書

> 狀態：草稿，已依 3 字原型的使用回饋修訂過一次（出題單位從 Sense 改回 Word，並定義中文意思的顯示格式）。目的是把玩法規則寫清楚，讓後續（不論是我或其他 AI）能直接依此實作，不用再回頭確認需求。
> 文末「開放問題／預設假設」列出了規格中原本模糊、我先做出合理預設的地方，實作前請 user 過目確認或修正。

---

## 1. 目的

建立一個獨立於現有「模擬考模式」（`toeic_mock_exam_mvp.html` 的 Part 1-7 模考）之外的**單字複習模式**。核心精神是「間隔重複 + 錯題收斂」：每次考試只考上一次答錯或標記不熟的字，直到使用者自己判斷已經記熟、手動結束循環為止。

這個工具（`cycle_mode_mvp.html`）對外顯示的名稱是 **Go Study Caterpillar**（分頁標題與頁面頂部標題列都用這個名字），取代原本的「TOEIC 循環模式」。

## 2. 單字庫（Vocabulary Bank）

### 2.1 定位

- 單字庫是**長期累積、持續成長**的資料集，使用者會不斷新增單字進去。
- 單字庫與「循環」是分開的兩個概念：單字庫是原始資料源，循環是拿單字庫做的一次複習活動。

### 2.2 資料結構

一個單字（Word）＝**一個英文原形**。同一個字底下可能有多種詞性、每種詞性底下可能有多個中文意思——這些全部收在同一個 Word 物件裡，不拆成獨立題目（見 2.3）。

```jsonc
Word {
  id: string,              // 唯一識別碼，例如 "w_0001"
  english: string,         // 英文原形，例如 "address"
  createdAt: string,       // ISO timestamp，新增時間
  wrongCount: number,      // 這個字累計答錯幾次（跨所有循環加總，永久保存）
  posGroups: PosGroup[],   // 至少 1 個，同一個字的不同詞性
  examples: Example[]      // 例句，可 0 個或多個，屬於整個字
}

PosGroup {
  pos: string,                  // 詞性縮寫，需精細到 vi / vt / nc（可數名詞）/ nu（不可數名詞）/ adj / adv / prep / conj / phr.（片語，見下方規則）... 等
  meaningGroups: string[][]     // 見下方「中文意思的顯示規則」
}

Example {
  en: string,               // 英文例句
  zh: string,                // 中文翻譯，預設隱藏，UI 上按「眼睛」圖示才顯示
}
```

### 2.3 出題單位

循環模式的「一題」＝**一個 Word**（不是詞性、不是意思）。一個字不論有幾種詞性、幾個意思，出題時只出現**一次**，把所有詞性與意思一起顯示在同一題裡，英文空格也只需要填一次。

> 修訂記錄：初版曾以「一個詞性+一個意思」（Sense）當作出題單位，會讓同一個英文字在同一輪裡重複出現好幾次（例如 `address` 出現 3 次）。使用者實測後回饋「大量重複」，故改為以 Word 為出題單位，並在題目卡片內把所有詞性/意思都列出來。

### 2.4 中文意思的顯示規則

一個 `PosGroup.meaningGroups` 是「意思群組」的陣列，每個群組本身又是字串陣列。規則如下：

1. **同一群組內、意思相近（同義詞）** → 群組內用**分號「；」**連接顯示。
   例：`["處理", "應付"]` → 顯示為 `處理；應付`
2. **同一詞性底下、意思差很多（不同義項）** → 拆成不同群組，顯示時**用數字編號**。
   例：`meaningGroups: [["處理","應付"], ["向…致辭","發表演說"]]` → 顯示為 `1. 處理；應付　2. 向…致辭；發表演說`
   （只有 1 個群組時不編號，直接顯示該群組內容）
3. **同一個字有多種詞性** → 每個詞性各自一行，格式為 `(詞性) 意思內容`，逐行往下疊放。
   例（`address`）：
   ```
   (vt) 1. 處理；應付　2. 向…致辭；發表演說
   (nc) 地址
   ```
   例（`run`）：
   ```
   (vi) 跑步
   (vt) 經營；管理
   ```

**判斷準則（同義詞用分號 vs. 不同義項用編號）**：如果兩個中文意思可以互相替換、是同一個概念的不同說法（如「處理」「應付」），用分號放在同一群組；如果是同一詞性下明顯不同的用法/概念（如「處理事情」vs.「向群眾致辭」），拆成不同編號群組。這個判斷目前由建立單字庫的人（使用者）自行決定分組方式，程式不自動判斷語意距離。

**規則：`meaningGroups` 裡不可以出現英文。** 中文意思欄位的用途是測驗時的提示，一旦裡面混入英文（例如把片語寫成「解釋（account for）」），等於直接洩漏部分答案。如果某個中文意思其實是依附在一個片語用法上（例如 "account" 作動詞的「說明、解釋」其實是 "account for" 這個片語才成立），**該片語必須獨立建立成一個新的 Word**（`english` 欄位＝整個片語，如 `"account for"`，`pos` 可標為 `phr.` 或類似），而不是把英文片語當附註塞進另一個字的中文意思裡。

### 2.5 wrongCount 的計算

- `wrongCount` 記在 **Word** 這一層，代表這個字有史以來被答錯的次數（跨所有循環累加，永久保存，不會隨循環結束而歸零）。
- 因為出題單位是 Word（2.3），每次考試每個字最多產生一次對/錯結果，所以 `wrongCount` 就是「這個字被判定錯誤的次數」的累加，不會有同一次考試裡重複計數的問題。

## 3. 循環模式（Cycle）整體流程

### 3.1 名詞定義

- **循環（Cycle）**：使用者手動開始、手動結束的一次複習活動。時間長短不固定。一個循環底下可以包含很多**次**考試。
- **次／考試（Attempt）**：一個循環裡的**一次**完整測驗（見第 4 節格式），用「次」計數與顯示（例如「第 1 次」「第 2 次」）。
  > 用語修訂：初版用「輪」當作這個單位的名稱，容易和「循環」混淆（口語上「一輪循環」常拿「輪」當循環的量詞）。改稱「次」之後，「循環」底下有「很多次考試」，語意更清楚：循環＝大容器，次＝容器裡的一筆一筆測驗紀錄。
- **循環錯誤題庫（Cycle Error Pool）**：僅存在於單一循環內的暫存集合，循環結束就整個丟棄（不影響單字庫本身的 `wrongCount`，那個是永久的）。Pool 裡存的是 **Word id**。

### 3.2 流程規則

1. 使用者按下「開始循環」→ 建立一個新的 Cycle，Cycle Error Pool 清空。
2. **第 1 次考試**：取單字庫「當下」的全部 Word 作為題目（若循環進行中使用者又新增了單字，新單字不會加入同一循環已經開始的考試，只會在下一次開新循環時被納入——見 6.4 開放問題）。
3. 使用者作答（見第 4 節格式）並交卷。
   - 答錯 **或** 被 flag 的 Word → 加入該循環的 Cycle Error Pool。
   - 答對且未 flag 的 Word → 這次考試之後不再出現於本循環。
4. 若 Cycle Error Pool 非空，使用者可選擇「開始下一次考試」：
   - **第 2 次起**：題目 = 上一次考試結束時的 Cycle Error Pool 全部 Word，**完全重新洗牌排序**（刻意打亂順序，避免使用者靠「上一題是什麼」的上下文記憶作答，而非真的記得單字）。
   - 交卷後：答對的 Word 從 Cycle Error Pool 移除；答錯或被 flag 的 Word 留在（或重新加入）Cycle Error Pool。
5. 重複步驟 4，直到滿足以下任一條件：
   - Cycle Error Pool 變空（代表這個循環裡的字都至少答對過一次且沒被 flag）→ 可自動提示「本循環已完成，是否結束？」。
   - 使用者在任何一次考試 **交卷後** 主動按下「結束循環」。
6. 循環結束 → 產生循環總結（見第 5 節），並把此次 Cycle 的紀錄存起來。

### 3.3 使用者何時可以「終止」

- 「終止循環」的操作點是在**每次考試交卷之後**（下一次考試開始之前），不是測驗進行中。
- 測驗進行中若想離開，是「暫停」（見 4.3），不是「終止循環」——暫停會保留當前這次考試的作答進度，之後可以回來繼續，不會被視為循環結束。

### 3.4 循環在首頁的呈現方式

- 首頁只有**一張**標題固定為「循環」的卡片，不論目前有沒有進行中的循環，都用這個標題（不再區分「開始新的循環」跟「進行中」兩種不同標題）。
- **沒有進行中的循環**時：卡片顯示簡短說明＋「開始循環」按鈕。
- **有進行中的循環**時：卡片直接列出這個循環目前為止**每一次考試**的紀錄（第 N 次‧還剩幾個不熟單字/總數‧交卷時間），**由新到舊排序（最新一次考試放最上面）**，不需要另外跳轉頁面才看得到。畫面上實際只顯示「N 次 · X/Y」，不會逐行重複寫出「個不熟單字」這種說明文字（意思在上面的段落說明過一次就夠）。每一次考試紀錄都有一個**「檢視」**按鈕，點下去會**跳轉到獨立的一頁**，顯示這次考試**答錯的單字清單**（全對時顯示「這次考試全部答對」），頁面上有「返回」可以回到原本按下「檢視」的地方。
  - 這個明細頁刻意做成**純白底、黑線表格，不用任何顏色色塊**（不套用其他畫面的金色/米色主題），維持樸素、專注在資料本身。
  - 標題精簡到只留**「N Round」**＋**交卷時間**（`YYYY/MM/DD HH:mm`，24 小時制），不重複列出交卷後還剩幾個不熟單字（那個資訊在上一層的列表已經看得到）。
  - **時間格式是全站統一規則，不是只有這一頁**：所有畫面上出現的時間戳記（每次考試的交卷時間、循環開始/結束時間、單字最近測驗時間…）都固定用 `YYYY/MM/DD HH:mm`、24 小時制、純數字，**不使用 `Intl`/`toLocaleString` 的中文在地化格式**（不會出現「上午/下午」這種中文字混在時間裡）。
  - 表格只有兩欄：**英文**、**詞性**（欄名就叫「詞性」，即使欄內同時顯示中文意思也一樣，不寫成「詞性／中文意思」）。
  - 頁面右上角有**「下載 PDF」**按鈕：透過瀏覽器原生列印（`window.print()`）搭配 `@media print` / `@page{ size:A4 }` 樣式輸出，使用者在系統列印對話框選「另存為 PDF」即可下載。列印時只印這張答錯單字表格本身（隱藏頂部導覽列、返回/下載按鈕），並鎖定 A4 尺寸＋留白，避免依賴任何外部 PDF 函式庫（維持整個工具是單一 HTML 檔、離線也能用的原則）。
  - **已知限制**：瀏覽器列印會自動加上「頁首/頁尾」（日期、網頁標題、網址、頁碼），這是瀏覽器層級的設定，網頁本身無法完全關閉。程式已把列印當下的 `document.title` 暫時清空，讓頁首中間不會顯示「TOEIC 循環模式」這個標題；但日期與網址仍會出現，若要完全去掉，使用者需要在系統列印對話框裡自行展開「更多設定」，把「頁首及頁尾」關掉（大多數瀏覽器會記住這個設定）。
  - 這份「每次考試」列表（含檢視按鈕）在首頁的循環卡片、單次考試結果頁、循環結束摘要頁、循環歷史的詳細頁都共用同一份元件，行為一致。卡片下方依狀態顯示可用動作：
  - 若有一次考試進行到一半（尚未交卷）→「繼續這次考試」。
  - 若剛交卷、Cycle Error Pool 非空 →「開始下一次考試」。
  - 只要不是考試進行中，隨時可以結束循環（呼應 3.3）——但**不是一個顯眼的大按鈕**。因為很容易被誤觸，改成卡片標題列**右上角一個小小的刪除圖示**，點下去還會跳出瀏覽器原生 `confirm()` 二次確認（「確定要結束這個循環嗎？」），確認後才真的執行 `endCycle()`。測驗進行中（`inProgress`）完全不顯示這個圖示，維持 3.3 的規則。首頁的「循環」卡片、單次考試結果頁都是這個做法。
  - 這個刪除圖示用**極簡風格的 inline SVG**（Material Design 的 delete 線條圖示，`fill="currentColor"`，跟著按鈕文字色變化），不用 emoji（🗑️ 這類 emoji 在不同系統/字型下顏色與細節不一致，畫面看起來會「太複雜」），維持整體樸素的視覺風格。
- **這是使用者的第幾個循環**（跨循環的序號）不在這張卡片裡顯示；要看歷史上開過幾次循環、各自的結果，去下方的「循環歷史」列表查看（先後順序即隱含序號，不需要額外編號欄位）。

## 4. 單次考試格式（Attempt UI）

### 4.1 題目呈現

- 每題顯示：**這個字的全部詞性與中文意思**，依 2.4 的格式逐行列出（每個詞性一行，同詞性內用分號/編號區分意思群組）。
- 英文完全留白，使用者只需要打**一次**英文原形（`english` 欄位）作答，不分詞性/意思。
- 不顯示例句（例句是單字庫瀏覽/複習用的參考資料，不在測驗時出現——見 6.4 開放問題）。

### 4.2 作答與 Enter 行為

- 輸入框中打字，按 **Enter**＝送出當前這題的答案（不論有沒有打字）並前進到下一題。
  - 有打字：以打的內容比對答案（大小寫不分、去除頭尾空白）。
  - 沒打字（直接按 Enter 跳過）：視為空白作答，一律判定為錯誤（不記得就跳過，等同答錯）。
- 測驗中**不能返回上一題修改**（維持每題獨立、不回頭的節奏，避免使用者靠後面題目回想前面題目）——見 6.4 開放問題（此為預設假設，非明確需求）。
- 每題右側/上方有 **Flag 按鈕**，使用者可隨時標記「不確定/不熟」，即使最後答對了，只要有 flag，這個 Word 一樣會被丟進 Cycle Error Pool。

### 4.3 計時與暫停

- 整次考試**不計時**（不顯示倒數或計時器）。
- 提供「暫停」功能：暫停時保留目前作答進度（已完成的題目與答案、剩餘題目與順序），可以離開頁面／關閉瀏覽器，之後回來能從暫停的地方繼續，不會被視為放棄或中斷循環。

### 4.4 交卷條件

- 必須把這次考試的**所有題目**都作答（含被跳過＝空白作答也算「已作答」）完，才能交卷看結果。
- 沒有「部分交卷」的概念。

## 5. 結算與複查（Results & Big Table）

### 5.1 單次考試結果

每次考試交卷後，立即顯示這次考試的結果列表（一列＝一個 Word）：

| 欄位 | 說明 |
|---|---|
| 英文 | 正確答案（Word.english） |
| 詞性／中文意思 | 依 2.4 格式，逐行列出所有詞性與意思 |
| 你的作答 | 使用者輸入的內容（含空白＝跳過） |
| 結果 | 正確 / 錯誤 |
| Flag | 是否被標記 |

### 5.2 總表（跨循環、可查找的大表）

- 除了「單次考試結果」，還需要一個**獨立於單一次考試、涵蓋整個單字庫**的總表（不只是這次考的字，而是整個單字庫目前的狀態）。
- 這個總表在**每次交卷後更新**，並且要能持久保存（不隨關閉瀏覽器消失）與**搜尋**（用英文或中文關鍵字過濾）。
- **畫面上的表格有分頁**：單字庫會持續變大，一次把全部單字渲染成 DOM 可能拖垮效能甚至讓頁面沒回應，所以畫面一次只顯示一頁（目前每頁 30 個字），底下有「上一頁／下一頁」按鈕，以及一個可以直接輸入頁碼跳頁的欄位（顯示「第 X / Y 頁，共 N 個字」）。搜尋框的關鍵字一變動，自動跳回第 1 頁重新計算頁數。
  - **分頁只影響畫面顯示，不影響下載 PDF**：下載 PDF 用的是另一份完整資料（見下方），永遠輸出「目前搜尋篩選後」的**全部**單字，不會因為畫面停在第 2 頁就只印第 2 頁的內容。
- 每一列**最右邊**有一個展開/收合的箭頭（accordion，預設收合），用**極簡風格的 inline SVG**（Material Design 的 chevron 圖示，`fill="currentColor"`，展開時旋轉 90°；不用純文字符號如「▸」，太小、不易點），點開後在該列下方插入一列顯示這個字的**例句**（`Word.examples`）。沒有例句的字，箭頭是灰階不可點的。
  - 每句例句先只顯示英文；中文翻譯預設隱藏，**英文句子的最右側**有一個「顯示中文」按鈕（跟英文同一行，用 flex 佈局靠右對齊，不是寫在下面另起一行），按下才顯示中文、文字變成「隱藏中文」可以再收回去——每句例句的顯示/隱藏各自獨立，不會因為展開別句就一起顯示。這個按鈕維持淺色外框、透明背景的樣式，**不用深色底**。
  - 這個展開狀態（accordion 開合、中文顯示與否）只是**畫面暫存狀態**，不存進 `localStorage`：重新整理頁面後全部預設收合，不需要持久化。
- 一列＝一個 Word（不再依詞性/意思拆列）。
- 「英文」欄位寬度設**最小寬度**（目前是 140px），避免自動排版把這欄擠得太窄。
- 頁面上也有**「下載 PDF」**按鈕，列印機制跟 3.4「檢視」明細頁一樣（`window.print()` + `@media print` + A4／頁首標題清空，見 3.4 已知限制），但**列印內容不是畫面上那份完整總表**，而是另外準備一份**跟「檢視」明細頁同一種極簡格式**的列印專用表格：
  - 只有兩欄：**英文**、**詞性**（用 `plainMeaningLines()`，跟「檢視」頁共用同一個純文字格式化函式，不帶色塊）。不印「錯誤次數」「最近結果」這些欄位，也不印展開箭頭那欄。
  - **不包含例句**：不論畫面上有沒有展開哪些字的例句 accordion，這份列印專用表格本來就不含例句內容。
  - 這份列印專用表格平常**在畫面上是隱藏的**（`display:none`），只有在 `@media print` 底下才顯示；畫面上正常顯示的完整總表（含搜尋框、下載按鈕、色塊、accordion）則反過來只在畫面上顯示、列印時整個隱藏。兩份內容資料相同（都套用目前的搜尋篩選），只是呈現方式不同。

> - 初版「目前所屬循環狀態」原本有 4 種細分值（尚未測／已通過／錯誤池中／已標記 flag），使用者回饋太長太細，先改成只分「進行中／無」兩種，後續使用者回饋這欄仍是多餘資訊，**整欄拿掉**，總表不再顯示循環狀態。

### 5.3 循環總結（Cycle Summary）

循環結束時（Error Pool 清空或使用者主動結束），額外記錄這次 Cycle 的摘要，存入「循環歷史」：

```jsonc
CycleRecord {
  id: string,
  startedAt: string,
  endedAt: string,
  totalRounds: number,            // 這個循環總共考了幾次（欄位名稱沿用 Round，顯示時一律說「次」）
  initialWordCount: number,       // 第一次考試出題的 Word 數
  finalMasteredCount: number,     // 最終答對且未 flag 移出 error pool 的 Word 數
  remainingUnmasteredCount: number, // 使用者提前結束時，還留在 error pool 裡的 Word 數
  endedReason: "pool_empty" | "user_terminated",
  roundBreakdown: {                // 每一次考試的逐次紀錄（對應 3.4／5.1 的「第 N 次」列表），循環結束後仍可查看
    roundIndex: number,            // 第幾次考試
    remaining: number,             // 那次交卷後，錯誤題庫剩幾個 Word
    total: number,                 // 分母，固定＝第一次考試的題數（initialWordCount）
    endedAt: string,               // 那次考試的交卷時間
    results: { wordId: string, userInput: string, correct: boolean }[]  // 那次考試每一題的作答結果，供「檢視」展開用（見 5.1a）
  }[]
}
```

## 6. 資料持久化與整合

### 6.1 儲存方式

- 沿用現有模考 MVP 已有的本地儲存模式（localStorage，並提供 gzip 匯出/匯入 JSON），單字庫、循環歷史、總表狀態都比照辦理，避免使用者要維護兩套備份機制。

### 6.2 與模考模式的關係

- 循環模式的單字庫，與模考模式（Part 1-7）目前的題庫（`QUESTIONS` / `AUDIO_DATA`）是**兩個獨立的資料集**，不互相依賴，但建議放在同一個網站（同一個 app）裡，用選單切換「模考模式」/「循環模式」。

### 6.2a 網站進入點（`index.html`）與「回到首頁」

- Repo 根目錄的 `index.html` 是**整個網站的進入點**（GitHub Pages 的預設首頁），內容只是一個轉址頁：把使用者導向 `mocktest/cycle_mode_mvp.html#home`。
- `cycle_mode_mvp.html` 平常會把 `state.screen` 存進 `localStorage`，重新整理或直接用網址列打開這個檔案時，會**恢復到使用者上次離開時所在的畫面**（例如單字總表、測驗中）——這是刻意設計的「暫停可以繼續」行為（見 4.3）。
- 但如果是**從根目錄 `index.html` 這個進入點**點進來的，網址列會帶 `#home` 這個 hash；`cycle_mode_mvp.html` 載入時若偵測到 `location.hash === "#home"`，會強制把畫面顯示成「循環模式主頁」，**不去恢復 localStorage 裡可能停在別的畫面的狀態**。
  - 這個強制只影響**當次要顯示哪個畫面**，不會覆寫 `localStorage` 裡實際存的 `state.screen`（沒有呼叫 `saveState()`）：如果使用者手上還有進行中的循環或測驗，資料完全不受影響，首頁的「循環」卡片一樣看得到、能繼續。
  - 沒有帶 `#home` 的一般網址（例如使用者自己把 `mocktest/cycle_mode_mvp.html` 加書籤、或重新整理），行為維持原樣，照常恢復到上次離開的畫面。
- 這個機制解決的實際問題：使用者上次測試時剛好停在「單字總表」，之後從網站首頁（根網址）重新進來，卻直接看到單字總表而不是循環模式主頁，體驗上很奇怪——所以進入點特地強制先顯示主頁。

### 6.3 視覺風格通則

- **全站不使用襯線字體（serif）**，統一用無襯線的黑體字型（`IBM Plex Sans` / `PingFang TC` / `Microsoft JhengHei` 這個 sans-serif 字型堆疊）。原本標題、詞義展示區用了 `Source Serif 4` 襯線字體營造「正式感」，使用者回饋不要有襯線字體，已經整個拿掉（包含 Google Fonts 的引入），全站文字改成單一字型風格，不分標題/內文。

### 6.4 開放問題／預設假設（實作前請確認）

以下是規格中原本沒明確講、我先選了一個合理預設的地方：

1. ~~出題單位是 Sense 而非 Word~~ **（已依實測回饋修訂：出題單位改為 Word，見 2.3）**
2. **測驗中不能返回上一題**：假設維持「一題定生死、按 Enter 就往前走」的節奏。如果你想要能回頭改前面題目的答案，這裡需要改。
3. **例句不出現在測驗中**：假設例句只在瀏覽單字庫時可看，測驗時完全不給提示。如果你希望測驗時也能看例句（甚至當提示的一部分），這裡需要改。**（已實作瀏覽單字庫看例句的部分：單字總表每列可展開 accordion 看例句，中文按鈕才顯示，見 5.2。測驗中仍然不顯示例句，維持原假設。）**
4. **循環進行中新增單字不會即時加入當次考試**：假設「第 1 次考試」抓的是「按下開始循環那一刻」的單字庫快照；使用者在循環進行中新增的字，要等下一次開新循環才會被考到。
5. **空白作答（跳過）一律算錯**：這會讓 `wrongCount` 增加。如果你希望「跳過」和「打錯」要分開統計（例如跳過不計入 wrongCount，只是不會從 error pool 移除），這裡需要改。
6. **Cycle Error Pool 變空時只是「提示」結束，不強制結束**：假設即使錯誤題庫空了，使用者仍可以選擇不結束、單字庫有新字時手動再開一次考試（但依規則 3.2-2，這其實等於要開新 Cycle，因為新字不會自動併入舊 Cycle）。這個邊界情況要再確認。
7. **flag 的作用範圍只在單一循環內**：假設 flag 狀態是每個循環各自獨立（不會跨循環保留），每次開新循環 flag 都會重置。如果你希望 flag 是永久標記（像「我一直對這個字沒把握」的標籤，跨循環都留著），這裡需要改。
8. **同義詞（分號）vs. 不同義項（編號）由人工分組，程式不判斷**：見 2.4 判斷準則。如果你希望之後能用工具輔助判斷語意相近度（例如自動建議分組），這裡需要另外討論。
