# 單字加入原則（給負責新增單字的 AI 看）

> 如果你被指派「幫忙加單字」到這個 TOEIC 循環模式單字庫，請先讀完這份文件再動手。這裡列的是**硬性格式規則**，不是建議——格式錯了會直接洩漏答案、造成重複出題，或讓程式壞掉。

## 0. 這份資料是做什麼用的

單字庫是給一個叫「循環模式」的單字複習功能用的：使用者每一題只會看到**詞性＋中文意思**，要自己把英文原形打出來。所以：

- 中文意思欄位＝考題的提示，**絕對不能包含任何英文**，否則等於洩題。
- 一個英文字（不分詞性、不分意思）只會出現成**一題**，所以同一個字的所有詞性/意思要收在同一個 Word 物件裡，不要拆成好幾個字分別加入。

現有資料在同目錄的 [vocab-bank.md](vocab-bank.md)（人類/AI 可讀版本）與 `cycle_mode_mvp.html` 的 `defaultWordBank()` 函式（程式實際讀的地方）。完整規格書在 [cycle-mode-spec.md](cycle-mode-spec.md)，這份文件是從裡面抽出跟「加字」直接相關的規則，濃縮版。

## 1. 資料格式（每個字長這樣）

```js
{
  id: "w25",                          // 見第 4 點
  english: "reimburse",               // 英文原形，字或片語都可以（見第 3 點）
  createdAt: new Date().toISOString(),// 固定寫法，照抄
  wrongCount: 0,                      // 固定 0，程式執行期才會累加
  stats: null,                        // 固定 null，程式執行期才會寫入
  posGroups: [                        // 至少 1 個，見第 2 點
    { pos: "vt", meaningGroups: [ ["償還","報銷"] ] }
  ],
  examples: [                         // 至少 1 個，見第 5 點
    { en:"The company will reimburse employees for approved travel expenses.", zh:"公司將報銷員工核准的差旅費用。" }
  ]
}
```

## 2. `posGroups` 怎麼寫（中文意思顯示規則）

一個字可以有多種詞性，每種詞性又可以有好幾個中文意思。規則：

1. **同一個詞性、意思相近（同義詞）** → 放進同一個陣列，用逗號隔開字串，畫面上會自動變成「；」分號連接。
   例：`meaningGroups: [ ["處理","應付"] ]` → 顯示 `處理；應付`
2. **同一個詞性、但是差很多的義項（不是同義詞，是完全不同的用法）** → 拆成不同的子陣列，畫面上會自動編號。
   例：`meaningGroups: [ ["處理","應付"], ["向…致辭","發表演說"] ]` → 顯示 `1. 處理；應付　2. 向…致辭；發表演說`
   判斷原則：兩個中文意思可以互相替換就是同義詞（用分號）；如果是明顯不同的概念/用法，才拆開編號。**不要為了炫技而過度拆分**，大多數字一個詞性只需要 1 個群組。
3. **同一個字有多種詞性** → 每個詞性各自寫一個 `{pos, meaningGroups}` 物件，放進 `posGroups` 陣列，畫面上每個詞性各自一行。
   例：`run` 是 `posGroups: [ {pos:"vi", ...跑步}, {pos:"vt", ...經營；管理} ]`

**詞性縮寫請盡量精細**，不要只寫 `n.` `v.`：

| 縮寫 | 意思 |
|---|---|
| `vt` | 及物動詞 |
| `vi` | 不及物動詞 |
| `nc` | 可數名詞 |
| `nu` | 不可數名詞 |
| `adj` | 形容詞 |
| `adv` | 副詞 |
| `prep` | 介系詞 |
| `conj` | 連接詞 |
| `phr.` | 片語（見第 3 點） |

## 3. 絕對禁止：中文意思欄位裡出現英文

`meaningGroups` 裡任何一個字串都**不可以包含英文字母**。這是最容易犯的錯，之前發生過把片語寫成「解釋（account for）」這種附註塞進中文意思裡，等於直接把答案寫在題目上。

如果某個意思其實是依附在一個片語用法上才成立（例如「說明、解釋」這個意思，其實是 `account for` 這個片語才有，單獨一個 `account` 不會這樣用），**該片語要獨立建立成一個新的 Word**，`english` 欄位就填整個片語（如 `"account for"`），`pos` 填 `"phr."`。不要把片語寫成任何一個字的中文意思附註。

## 4. `id` 規則

- 格式固定 `w` + 數字，接續現有最大編號往後加。**加字前先打開 [vocab-bank.md](vocab-bank.md) 確認目前最大的 id 是多少**，不要憑空編號，也不要重複使用已存在的 id。
- 每個 `id` 對應唯一一個英文字/片語，不可以重複。加字前先確認 `english` 沒有已經存在於 [vocab-bank.md](vocab-bank.md) 裡（大小寫不分、去除頭尾空白後比對）。

## 5. `examples`（例句）規則

- 每個字至少要有 **1 句**英文例句＋對應的繁體中文翻譯。
- 如果一個字有多種詞性/義項，**盡量每種詞性/義項都配一句例句**，讓使用者知道實際用法（不是強制，但強烈建議，尤其詞性差很多時）。
- 例句要是完整、自然的句子，情境盡量落在**職場/商業**（TOEIC 常考場景：辦公室、會議、行銷、財務、人資、物流、客服等），不要用太生活化或跟考試無關的例句。
- 中文翻譯必須是**繁體中文**，語意要通順、不要逐字硬翻。

## 6. 難度與選字方向

- 目標是幫使用者考到 **TOEIC 900 分以上**，所以請選**中高階商業／職場詞彙**，不要選國中基礎單字（如 apple、happy 這種）。
- 優先選會在 TOEIC 閱讀/聽力常見主題出現的字：辦公室行政、會議、人資、財務會計、行銷業務、物流採購、客服、法律合約、製造品管等。
- 避免加入意思跟現有單字庫（[vocab-bank.md](vocab-bank.md)）裡已經有的字**高度重複**的同義詞，除非是使用者明確要求擴充同義詞群。

## 7. 你輸出的格式

新增的每個字，請照**第 1 點的格式**、用同一種縮排/風格，直接輸出成可以貼進 `defaultWordBank()` 陣列的 JS 物件（跟 [vocab-bank.md](vocab-bank.md) 裡現有的寫法一模一樣）。

**不要**：
- 不要改動 [vocab-bank.md](vocab-bank.md) 或 `cycle_mode_mvp.html` 裡已經存在的字，除非使用者明確要求修正錯誤。
- 不要自己發明新的資料欄位或改變既有欄位名稱（`id` / `english` / `createdAt` / `wrongCount` / `stats` / `posGroups` / `pos` / `meaningGroups` / `examples` / `en` / `zh` 這幾個名字要完全照抄）。
- 不要只更新 `vocab-bank.md` 就以為完成了——這份 md 不會被網頁讀取，實際要生效還需要有人把新的物件貼進 `cycle_mode_mvp.html` 的 `defaultWordBank()` 陣列裡（如果你有能力編輯這個檔案，兩邊都要同步更新；如果沒有，就只要把新字的 JS 物件產出來交給使用者或下一個負責整合的 AI）。

## 8. 交付檢查清單（自己對一次）

- [ ] 每個新字的 `id` 沒有跟現有的重複，且接續現有最大編號
- [ ] `english` 沒有跟現有單字庫重複
- [ ] `meaningGroups` 裡每個字串都**沒有英文**
- [ ] 片語用法都獨立成自己的 Word，沒有塞進別的字的中文意思裡當附註
- [ ] 同義詞用同一個陣列（分號），差很大的義項才拆成不同陣列（編號）
- [ ] 每個字至少 1 句例句，中文是繁體
- [ ] `pos` 用的是精細縮寫（vt/vi/nc/nu/adj/adv/prep/conj/phr.），不是籠統的 n./v.
- [ ] 選字方向是 TOEIC 900+ 商業／職場詞彙，不是基礎單字
